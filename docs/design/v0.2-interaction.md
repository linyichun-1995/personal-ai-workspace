# V0.2 页面与交互设计

更新日期：2026-09-18  
状态：二期交互规格，沿用一期组件与视觉规范

[二期总览](../product/v0.2-plan.md) · [需求规则](../product/v0.2-requirements.md) · [UI 设计系统](ui-design-system.md)

## 1 信息架构

一期的核心问题是入口过多和下一步不明确。二期只增加必要的文件入口，搜索放在顶部，标签藏在内容组织流程与设置中。

```text
顶部
  全局搜索                         快捷导航

主导航
  概览
  项目
    项目详情 → 任务 / 笔记 / 文件
  任务
    任务详情 → 标签 / 附件
  笔记
    笔记详情 → 标签 / 附件
  文件
    全部 / 未分类 / 回收站
  设置
    保留已有分区 / 标签管理
```

全局搜索和快捷导航是不同入口。前者查内容，后者创建对象或打开页面；不把未上线的 AI、语义搜索或集成能力混入任一入口。

## 2 页面与路由

实际项目路由以 `/app` 为前缀，二期不采用一期规划中已过时的无前缀示例。

| 页面 | 建议路由或参数 | 行为 |
| --- | --- | --- |
| 文件列表 | `/app/files?view=all&q=...&page=1` | 服务端筛选与分页 |
| 文件详情 | `/app/files/$fileId?from=...` | 独立可分享的站内位置，保留来源 |
| 全局搜索 | `/app/search?q=...&types=NOTE&page=1` | 查询和筛选写入白名单参数 |
| 项目文件 | 现有项目详情加 `tab=files` | 保留一期项目来源和页码约定 |
| 标签设置 | `/app/settings/tags` | 复用已有设置布局，实施时补入路由树 |
| 任务附件 | 现有任务详情/编辑区域 | 不创建第二套任务详情 |
| 笔记附件 | 现有笔记编辑页辅助区域 | 不替换 Markdown 编辑器 |

表中路由是拟新增设计。列表 view=all 映射 API view=active；“未分类”映射 uncategorized=true，由服务端查询无项目且无标签的内容；trash 映射回收站。列表高级筛选提供“包含归档项目文件”，默认关闭，不能仅在当前页客户端筛选。

from 只接受应用内已知路由和白名单参数，不能成为开放跳转 URL。浏览器刷新和返回都保留查询上下文；列表数据仍从服务端重新校验。

## 3 文件资料库

### 3.1 页面结构

顶部显示“文件”、简短容量提示和唯一主按钮“上传文件”。第二行放全部/未分类/回收站分区；第三行放项目、标签、格式、状态和名称筛选。

桌面列表列为名称、类型、项目、标签、处理状态、大小、更新时间和操作。文件名是主入口，行内仅保留下载和更多操作。首版不显示不能使用的文件夹树、多人头像、分享按钮或版本历史。

移动端改为卡片式行，名称和状态始终显示，其他信息折叠为一行摘要；筛选进入抽屉。不能让横向滚动成为完成上传和下载的前提。

### 3.2 上传流程

```mermaid
flowchart LR
  A[选择或拖入文件] --> B[显示格式 大小 项目与剩余容量]
  B --> C[逐个上传]
  C --> D[上传成功]
  C --> E[失败并保留原因]
  D --> F[正文处理中或仅名称可搜]
  F --> G[添加标签或关联到当前内容]
  E --> C
```

上传队列每项显示文件名、字节传输进度和状态。传输到 100% 时显示“正在确认文件”，服务端确认后才显示“上传成功”。正文提取另显示“处理中”，不把传输进度延长成不可解释的 99%。

支持移除尚未开始的队列项；活动上传可取消客户端请求，但须说明服务端正在核对状态。再次进入页面后按 uploadId 查询结果，避免网络超时就重复创建。首版跨页面刷新不承诺自动恢复本地文件字节或自动续传。

上传成功后刷新当前列表；从项目进入时保留项目筛选，从任务/笔记进入时优先建立关联并返回原位置。关联失败提示“文件已上传，关联未完成”，提供重试。

### 3.3 文件详情与删除

详情上部为名称、项目、标签和操作；主体为预览；下方为文件信息和引用位置。处理失败时在预览区域解释原因，仍保留允许的下载操作。

删除确认说明是否有引用、文件将进入回收站及保留 30 天；请求期间显示处理状态并禁用重复提交，失败时对话框不消失。删除成功返回原列表，保留筛选；当前页为空时提供返回上一页或第一页的操作。

回收站显示删除时间、剩余保留期和删除来源。父项目已删除的文件显示“随项目删除，暂不能单独恢复”；父项目归档则引导先恢复项目可写状态。回收站文件仍占用容量，页面中明确显示这一规则。

## 4 项目任务笔记中的附件

项目详情增加“文件”分区，空状态只有“上传文件”。任务和笔记附件区提供“上传文件”“选择已有文件”；选择器默认限制在同项目范围，不先展示不允许选的文件再报错。

附件区不影响任务正文或笔记 Markdown 的保存状态。上传队列由 File 模块维护，笔记草稿继续由已有串行自动保存逻辑维护。离开有未保存正文的笔记仍触发一期保存保护。

附件卡片显示名称、格式、大小和正文处理状态。已删除文件只显示不可用提示和移除引用操作，不提供可点击旧下载地址。删除任务或笔记时，文案明确附件引用会被解除，资料库原文件保留。

归档项目相关页面标明只读；上传、解绑、删除、重命名和重新处理入口禁用并解释原因。用户可以正常查看和下载已有资料。

## 5 标签交互

标签使用现有语义色，不为颜色加入新的主题体系。选择器按名称搜索，已选标签显示移除按钮；输入无匹配时提供“创建标签”，先显示规范化冲突和长度错误。

设置页显示名称、颜色、使用数量和操作。重命名成功后所有页面更新显示；删除确认展示影响数量，并说明内容不会被删除。删除失败保留当前面板。

多标签筛选明确显示“满足全部”或“满足任意”，不能只放两个含义不明的英文缩写。点击对象上的标签，进入带该标签的全局结果页；原对象上下文记录在来源参数中。

标签集合保存期间保留操作状态。发生并发冲突时展示“标签已在其他位置修改”，允许重新加载并再次选择，不自动覆盖。

## 6 全局搜索

顶部搜索输入提示“搜索项目、任务、笔记和文件”。提交后进入搜索页；搜索页输入采用约 300ms 合并和请求取消，旧请求晚返回不能覆盖新查询。中文输入法组合期间不发出半成品查询。

建议全局搜索使用 Ctrl/Command + Shift + F，快捷导航保留现有绑定；实现前核对项目已有快捷键，冲突时优先使用清晰可点击入口。快捷键不在富文本输入或浏览器特殊上下文中强行截获。

结果页顶部保留查询框，接着是类型、项目、标签、更新时间、包含归档和排序；下面显示结果数及分页。结果条目包含类型图标、标题、命中摘要、项目、标签和时间。归档结果显示只读标识。

打开结果后回到业务详情，返回时恢复 URL 条件和页码；首版不承诺笔记内精准跳到某一行或 PDF 自动跳到某一页。结果已经被删除时显示“内容已不存在或不可访问”和返回搜索入口。

## 7 统一状态与文案

| 状态 | 主要内容 | 推荐操作 |
| --- | --- | --- |
| 文件库首次为空 | 还没有文件，把常用资料放到这里 | 上传文件 |
| 筛选无结果 | 没有符合当前条件的文件 | 清除筛选 |
| 搜索未输入 | 输入关键词，或选择类型、项目和标签 | 继续输入/选择筛选 |
| 一字查询 | 至少输入 2 个字符后搜索 | 保留输入 |
| 正常搜索无结果 | 没有找到匹配内容 | 检查关键词、清除筛选 |
| 索引积压 | 部分新内容仍在处理中 | 稍后刷新；已有结果继续可用 |
| 搜索请求失败 | 搜索暂时不可用 | 重试，不显示 0 条伪结果 |
| 正文解析失败 | 原文件已保存，正文暂不可搜索 | 下载原文件；可重试时提供重试 |
| 配额不足 | 容量不足，回收站中的文件也占用空间 | 查看容量与回收站 |
| 权限或对象失效 | 内容已不存在或不可访问 | 返回原列表 |

错误信息显示业务原因，requestId 放在可展开详情用于排查。用户流程不展示数据库、队列、解析器栈和对象存储内部路径。

## 8 交互验收

核对 390px、768px、1440px，深浅主题，键盘操作和减少动态效果。标签不能只靠颜色区分，处理状态不能只靠图标区分，上传进度和失败信息可被辅助技术读取。

弹窗遵循现有 DraftDialog 和焦点管理规则。搜索筛选变化回到第一页；后台数据刷新不抢输入焦点；文件预览关闭后释放内容 URL；所有新增入口必须指向真实可用功能。
