## 1 当前部署记录

用户已明确说明 RustFS 镜像已经运行。接入复用该实例，项目根 Compose 暂仍只管理原有 PostgreSQL 和 Redis，不因编写文档再次启动同名 RustFS。

| 项目 | 用户提供的值 |
| --- | --- |
| 容器与服务名 | rustfs |
| 镜像引用 | rustfs/rustfs:latest |
| 重启策略 | unless-stopped |
| S3 API | 宿主机 9000 → 容器 9000 |
| Web Console | 宿主机 9001 → 容器 9001 |
| API 监听 | RUSTFS_ADDRESS=:9000 |
| 控制台监听 | RUSTFS_CONSOLE_ADDRESS=:9001 |
| 控制台开关 | RUSTFS_CONSOLE_ENABLE=true |
| 持久化挂载 | E:/docker-data/rustfs → /data |
| 启动参数 | /data |
| 根凭据 | 已通过 RUSTFS_ACCESS_KEY/RUSTFS_SECRET_KEY 设置；文档不复制 Secret 值 |

整理后的 Compose 结构如下，仅用于阅读和后续维护；凭据引用改为占位环境变量，不能把此示例当作本轮已应用配置。

```yaml
services:
  rustfs:
    image: rustfs/rustfs:latest
    container_name: rustfs
    restart: unless-stopped
    ports:
      - "9000:9000"
      - "9001:9001"
    environment:
      RUSTFS_ACCESS_KEY: ${RUSTFS_ACCESS_KEY}
      RUSTFS_SECRET_KEY: ${RUSTFS_SECRET_KEY}
      RUSTFS_ADDRESS: ":9000"
      RUSTFS_CONSOLE_ADDRESS: ":9001"
      RUSTFS_CONSOLE_ENABLE: "true"
    volumes:
      - E:/docker-data/rustfs:/data
    command: /data
```

官方 Docker 文档说明 9000 与 9001 分别承担 S3 API 和 Console；接入 SDK 应使用前者。[RustFS Docker 指南](https://docs.rustfs.com/en/installation/container/docker)

`latest` 不能标识一个可复现版本。后续只读登记当前容器镜像 ID 和对应 RepoDigest，连同 SDK BOM 进入验收记录；是否固定到该摘要属于后续部署步骤，不在本轮重拉或重建。

## 2 按后端运行位置选择地址

| 后端在哪里运行 | S3 endpoint | 前提 |
| --- | --- | --- |
| 当前 Windows 宿主机，Gradle 启动 | `http://127.0.0.1:9000` | 当前端口映射可达 |
| Docker Desktop 中的另一容器，经宿主机访问 | `http://host.docker.internal:9000` | 已验证宿主解析及端口可达 |
| 与 RustFS 处于同一个用户定义 Docker 网络 | `http://rustfs:9000` | 两个服务实际加入同一网络；同名不代表天然互通 |
| 远程部署 | 管理员提供的内网 HTTPS S3 地址 | TLS、网络和路由验证通过 |

容器内部的 localhost 指向容器自身。控制台地址 `http://127.0.0.1:9001` 只供管理员使用，不作为应用 endpoint。S3 endpoint 不包含 bucket 名或 `/api/v1`，桶路径由 SDK 的 Path Style 生成。

Path Style 使用 `endpoint/bucket/key`，不要求为每个桶配置 DNS。当前建议显式启用这一模式。[RustFS Path Style](https://docs.rustfs.com/en/integration/virtual)

## 3 桶与凭据准备

采用每环境一个专用私有桶；建议开发桶 `personal-ai-workspace-dev`，测试桶 `personal-ai-workspace-test`。桶名是本项目建议值，尚未确认已经存在。

后续接入顺序：

1. 在现有控制台确认当前服务版本、可用磁盘与网络地址。
2. 使用管理身份新建专用私有桶，确认从未开启版本控制、未启用对象锁，没有匿名读写策略。
3. 建立应用身份或 Access Key，仅授予目标桶与应用前缀的必要权限。
4. 将应用凭据注入后端进程，不放入前端 `VITE_*`、Git 文件或 API 响应。
5. 运行 P2-027 兼容矩阵，登记镜像摘要、SDK 版本、region、桶状态和策略。

用户给出的根凭据用于现有实例管理；应用常驻访问改用专用凭据。RustFS 官方区分根身份与 IAM 用户/访问密钥，策略能力仍需与当前已运行镜像核对。[RustFS IAM](https://docs.rustfs.com/en/security-compliance/iam)、[凭据管理](https://docs.rustfs.com/en/operations/credentials)

建议权限范围如下，属于待验证策略示例；应用桶已经由管理员准备，运行身份不负责创建和删除桶。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:GetBucketLocation", "s3:GetBucketVersioning"],
      "Resource": "arn:aws:s3:::personal-ai-workspace-dev"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": [
        "arn:aws:s3:::personal-ai-workspace-dev/workspaces/*",
        "arn:aws:s3:::personal-ai-workspace-dev/integration-probes/*"
      ]
    }
  ]
}
```

这是身份策略，避免误当作含匿名 Principal 的公共桶策略。ListBucket 作用于专用桶，用于 HeadBucket/对账；对象读写限于上述前缀。它不提供应用用户间的 Workspace 隔离，后者由 File 服务保证。若进一步限制 ListBucket 的 prefix，必须验证没有使无 prefix 的桶探针失效。[RustFS 策略格式](https://docs.rustfs.com/en/security-compliance/iam/policies)

## 4 应用配置契约

以下是拟新增 `app.storage` 配置，当前应用尚未绑定这些字段。仓库不会自动加载后端目录 `.env`；后续由进程环境、IDE 启动配置或部署密钥注入。

```yaml
app:
  storage:
    provider: S3
    profile-id: rustfs-local
    enabled: true
    s3:
      endpoint: ${STORAGE_S3_ENDPOINT:http://127.0.0.1:9000}
      region: ${STORAGE_S3_REGION:us-east-1}
      bucket: ${STORAGE_S3_BUCKET:personal-ai-workspace-dev}
      access-key: ${STORAGE_S3_ACCESS_KEY}
      secret-key: ${STORAGE_S3_SECRET_KEY}
      path-style: true
      auto-create-bucket: false
      expected-versioning: NEVER_ENABLED
      integrity-mode: READBACK_SHA256
      connect-timeout: 3s
      connection-acquisition-timeout: 2s
      socket-timeout: 30s
      attempt-timeout: 45s
      call-timeout: 120s
      max-attempts: 3
      max-connections: 32
    spool:
      directory: ${STORAGE_SPOOL_DIRECTORY}
      max-total-bytes: 536870912
      max-concurrent-uploads: 4
```

`expected-versioning` 和 `integrity-mode` 是项目封装定义的枚举，不是 RustFS 环境变量。客户端每批 2 个上传，服务端每实例总并发初值 4，二者作用范围不同。临时目录总容量初值 512MiB，单文件仍限制 20MiB。

Windows 临时目录建议 `E:/docker-data/personal-ai-workspace/upload-spool`，与 `E:/docker-data/rustfs` 分离；容器环境使用单独受限临时卷。服务启动时校验它是专用路径，清理只处理系统生成且已过期的临时文件。

region 初值 `us-east-1` 来自 RustFS 当前官方说明，用户实例未显式提供 region，仍须联调验证。[RustFS S3 协议配置](https://docs.rustfs.com/en/administration/protocols/s3)

配置失败只使文件能力不可用并拒绝相关写入；一期登录、项目、任务和笔记应继续工作。禁止存储故障时静默退回本地目录，以免同一 fileId 产生不同数据来源。

## 5 后端 HTTP 适配注意事项

当前后端使用 WebMVC，上传设计为单文件原始字节 PUT。不能只配置 multipart 上限却漏掉原始请求体限制；网关、控制器接收流和临时文件限额都应执行大小检查。

当前 CORS allowed-headers 只有 Authorization、Content-Type、X-Request-Id 等既有项。若前后端跨源部署，增加 Idempotency-Key 与 If-Match 的白名单；需要前端读取的 Content-Disposition、X-Request-Id、Retry-After 应显式暴露。开发走 Vite 同源代理时也要保留生产跨源验收用例。

P0 浏览器只访问应用 API，不访问 RustFS，不需要为上传功能开放 RustFS 的全来源 CORS。控制台跨源设置属于独立管理界面配置。二进制上传/下载在 Scalar 中标明对应 media type，不继承所有接口均为 JSON 的假设。

## 6 只读排查命令参考

下列命令仅为后续排查文档，本次没有执行。不要输出容器完整环境，因为其中可能包含 Secret。

```powershell
docker ps --filter name=rustfs --format '{{.Names}} {{.Image}} {{.Status}} {{.Ports}}'
docker inspect rustfs --format '{{.Image}}'
Invoke-WebRequest -Uri 'http://127.0.0.1:9000/health' -Method Get
```

当前官方 Docker 文档使用 `/health`；旧镜像若路径不同，应核对实际版本，不以 404 单独判断对象存储已损坏。健康检查只能证明服务入口状态，不能证明应用凭据能读写目标桶；写入与删除探针只在受控验收中运行。

| 症状 | 优先核对 |
| --- | --- |
| Connection refused | 后端所在网络、9000 映射、容器状态 |
| 返回 HTML 或控制台页面 | 是否误用了 9001 或反向代理路径 |
| 签名错误、跳转或 403 | endpoint、region、Path Style、实际应用凭据、服务时钟 |
| HeadBucket 403 | 桶级策略是否允许必要检查；不能自动当作桶不存在 |
| 小文件可以，大文件超时 | 接收/代理超时、确切长度、spool 限额、SDK 尝试预算 |
| 上传 400 或 checksum 不兼容 | 已锁定 SDK 与镜像组合、请求校验头/传输编码，不先全局关闭校验 |
| 无法删除或容量不回落 | 版本控制、对象保留、应用软删除和物理清理状态 |
| 存储中有文件而业务看不到 | 是否是未发布候选；按上传尝试和事务记录对账 |

## 7 备份与维护

`restart: unless-stopped` 和宿主目录持久化不等于备份。当前单实例部署应记录单点故障范围；本期不把它描述成已具备多节点高可用。

备份以数据库一致点、已发布 ObjectRef 清单和对象字节组成可恢复集合。复制 RustFS 底层目录需要遵守所用版本的停写或一致快照方式，不能假设运行中直接复制目录即可恢复。应用按 S3 对象导出备份时也要记录 SHA-256 与桶配置，并保留单独的凭据恢复流程。

升级先记录镜像摘要和兼容结果，再备份、停写或按既定窗口切换。不要因为示例使用 latest 就自动重拉运行实例，也不要自动清空 bucket 或宿主数据目录。
