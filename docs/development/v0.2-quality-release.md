## 1 验收策略

按用户闭环、权限与一致性、故障恢复、性能、一期回归五个维度验收。界面可点击不等于文件已可靠保存；查询有结果不等于范围与删除规则正确。P0 每一项必须关联可重复的输入和实际结果。

后端使用真实 PostgreSQL 16 验证索引、外键、并发和迁移；存储验证用户 RustFS 镜像与锁定 AWS SDK v2 的实际组合，按 [S3-01 至 S3-17](v0.2-s3-acceptance.md)记录协议及失败行为。解析使用测试部署的真实适配器。前端单元测试可使用契约样例，最终端到端必须连接当前真实后端。

当前一期部分 E2E 在后端缺失或版本不匹配时会 skip。二期发布检查必须读取通过、失败和跳过数量；核心流程的跳过视为未验收，不能以命令退出成功代替验证成功。

## 2 固定测试数据

- 至少 3 个账号、2 个互不授权的 Workspace，保留相同文件名和标签名，故意制造猜测 ID 的负例。
- 项目包含活动、归档、已删除；任务包含进行中、完成、取消和一级子任务；笔记包含收藏、归档、未保存草稿与版本冲突。
- 合法文件至少覆盖中文文本 PDF、DOCX、UTF-8 TXT/MD、PNG/JPEG/WebP；另有无文本、扫描、加密、损坏、超限、伪装类型和过度解包样本。
- 文件边界包含 0 字节、20MiB、20MiB+1 字节、声明与实际大小不符、同名不同内容、同内容不同提交、已完成会话重复提交。
- 测试样本不包含真实用户私密资料；异常样本仅在受限测试环境使用，不执行上传文件中的代码。

空字节 TXT/MD 可保存并标记 EMPTY；空 PDF/DOCX 必须在接收校验阶段拒绝为非法文档。TXT/MD 编码按需求规定验证 UTF-8 和 UTF-8 BOM，不能由前后端各自猜测。

## 3 功能与可靠性用例

| 用例组 | 关键操作 | 期望结果 | 追踪 |
| --- | --- | --- | --- |
| Q01 文件接收 | 上传、刷新、下载并比较 SHA-256 | 字节一致；元数据和容量正确 | AC01 |
| Q02 幂等与并发 | 同键重试、同键不同参数、同时接收、并发占额 | 不覆盖、不重复计费；冲突明确 | AC02、AC03 |
| Q03 失败补偿 | 写存储成功后数据库失败、接收中断、会话超时 | 临时对象可清理，容量可恢复，无假成功 | AC03、AC15 |
| Q04 文本处理 | PDF/DOCX/TXT/MD 与图片、扫描、加密样本 | 状态和正文范围正确，原文件仍可按规则访问 | AC04 |
| Q05 Worker 故障 | 强制重启、租约过期、重复与乱序任务 | 幂等完成或明确失败；旧结果不能发布 | AC05、AC15 |
| Q06 附件与移动 | 挂载、重复挂载、解绑、任务改项目 | 原文件不丢失；跨范围拒绝 | AC06、AC07 |
| Q07 标签 | 重名竞争、重命名、删除、标签集合冲突 | 唯一性与版本正确；对象不删除 | AC08、AC09 |
| Q08 搜索匹配 | 四类对象、中文两字、英文和混合、多项、特殊符号 | 语义与排名符合约定，无字符组假阳性 | AC10 |
| Q09 搜索筛选 | ALL/ANY、类型、项目、时间、归档和分页 | items、total 和理论页数同条件 | AC11 |
| Q10 来源返回 | 搜索打开任务/笔记/文件，再后退、刷新 | 查询、筛选与页码保持，失效内容有返回入口 | AC12 |
| Q11 Workspace 隔离 | 猜测他人 ID、标签、附件、内容和搜索条件 | 无结果、摘要、计数、文件字节泄漏 | AC13 |
| Q12 生命周期 | 搜索投影未更新时删除、解析中删除、项目级联 | 新请求立即不可见，不能被旧任务复活 | AC13、AC14 |
| Q13 回收站与清理 | 恢复、父级归档/删除、到期删除对象失败 | 恢复受限；清理失败不释放容量；最终可重试 | AC14 |
| Q14 索引重建 | 后台回填期间继续编辑和删除，然后切换 | 当前结果正确，无版本回退或半成品接管 | AC15 |
| Q15 保存与布局 | 上传时继续编辑笔记、冲突、键盘、手机布局 | 草稿安全、操作可达、错误可理解 | AC16 |

并发测试必须控制事务和 worker 的交错顺序，至少覆盖“解析先开始，删除后提交，解析最后完成”和“旧版本索引任务晚于新版本到达”。仅顺序执行接口无法验证这些风险。

## 4 搜索质量与性能

### 4.1 参考环境和样本

建议参考环境：4 vCPU、8GiB RAM、SSD，数据库和 API 同机或同可用区，独立受限解析进程。记录 OS、JDK、PostgreSQL、依赖版本、容器资源和数据分布；不同环境的结果不能直接比较。

准备 5 万条索引对象，当前被测 Workspace 占 4 万条，另一个隔离 Workspace 占 1 万条；四种对象均有覆盖，正文平均约 4000 字符，另包含接近 200000 字符的长文档和大量高频短词。报告索引总大小、构建时间和磁盘使用量。

人工标注 60 条查询，各指定一个应找回的目标：中文两字 15 条、中文长词 15 条、英文 10 条、混合词 10 条、多关键词 10 条。另设权限、无结果和特殊字符集合，它们属于正确性验收，不混入“前 5 条命中率”的分母。

### 4.2 指标与测法

| 指标 | 测量方式 | 发布目标 |
| --- | --- | --- |
| 搜索请求延迟 | 预热 5 分钟，再以 10 并发持续 15 分钟；包含数据库匹配、授权、total 和摘要 | P95 ≤ 800ms；请求错误率 < 1% |
| 高峰与冷查询 | 冷缓存和高频短词单独报告，不与预热数据混合 | 不触发无限制扫描或拖垮一期 API；不达标须说明和修复 |
| 目标找回率 | 固定 60 条中，目标出现在前 5 条的查询数 / 60 | ≥ 90%；安全负例仍必须 100% 通过 |
| 索引新鲜度 | 记录业务提交时间，到搜索首次可见的差值 | P95 ≤ 5 秒 |
| 文件正文可搜时间 | 标准文本型文件 ≤ 5MiB，低负载，从接收成功到正文命中 | P95 ≤ 60 秒 |
| 提取成功率 | 至少 40 份有效、支持、未加密样本，READY 或合理 EMPTY / 总数 | ≥ 95%；EMPTY 必须与人工判断一致 |
| 一期性能回归 | 比较同环境已有关键 API 的相同样本 | P95 相对基线退化不超过 20% |

目标只对上述条件有效。最大文件和并发提取单独测资源与可恢复性，不能据 5MiB 样本对所有格式承诺 60 秒。浏览器端记录交互等待，但不将公网网络耗时混入 API 延迟指标。

## 5 发布门槛

- P2-001 至 P2-027 全部有完成记录，AC01 至 AC16 以及 S3-01 至 S3-17 均有对应证据；恢复证据可由 P2-024 共享给 P2-027。
- 阻塞与严重缺陷为零；隔离、数据损失、删除失效、原文件不一致和无法恢复均属于阻塞。
- 一期登录、刷新、资料/Workspace 设置、项目任务笔记编辑、自动保存和概览路径通过。
- 空库和一期存量库迁移通过，jOOQ 生成、类型检查、构建及相关测试通过；核心测试无 skip。
- 性能和质量指标达到目标；例外须更新范围与计划，不能只写“后续优化”后宣布达标。
- 备份恢复、索引重建、关闭入口、停止领取任务与回滚演练有记录。

拟执行的工具沿用现有开发指南：前端类型检查、lint、构建、Vitest 和 Playwright；后端 Gradle 测试、jOOQ 生成与构建。实际命令和测试筛选以实施时仓库配置为准，本次文档工作不执行应用测试。

## 6 配置和发布顺序

建议新增配置开关：`files.enabled`、`fileExtraction.enabled`、`tags.enabled`、`search.enabled`、`jobs.claimEnabled`、`filePurge.enabled`。这些是拟定配置，不是现有配置项。权限、文件生命周期检查和事件持久化属于一致性基础，不能随 UI 开关关闭。

1. 记录当前制品、数据库版本、已运行 RustFS 镜像摘要、SDK BOM 和桶版本模式，备份数据库与私有对象，验证备份可读取；不重复部署同名容器。
2. 执行新增表与约束迁移，默认关闭面向用户的新增入口和到期物理清理。
3. 部署理解二期数据结构的新后端，验证认证、一期读写、RustFS 应用凭据/私有桶、完整性策略与解析隔离；S3 探针不把普通 403 当成桶或对象不存在。
4. 启用 worker，回填一期项目、任务和笔记投影，核对数量、源版本和随机抽样。
5. 先在受控 Workspace 开放文件、标签和搜索，执行固定演示与安全负例。
6. 观察至少 1 个工作日的上传失败、解析资源、索引延迟、搜索耗时和一期错误率；这是一项建议观察窗口，不保证覆盖所有长期风险。
7. 满足门槛后扩大开放；文件物理清理最后启用，并先进行只列清单的 dry-run。

灰度必须前后端同范围控制，不能仅隐藏导航后仍允许所有账号调用未准备好的写接口。

## 7 回滚与恢复

首选回滚方式是关闭二期用户入口和新增写入，保留理解二期表结构及生命周期的兼容后端。不能直接回到未经二期改造的一期后端继续写数据，否则项目删除、附件移动和搜索事件会漏处理。

### 7.1 搜索故障

关闭搜索入口，保持一期业务和变更任务持久化；必要时暂停索引消费者而非丢弃事件。切回已验证的旧 indexGeneration，或重建后追平再启用。投影故障不需要恢复整个业务数据库。

### 7.2 文件处理故障

暂停新提取任务领取，保留原文件和待处理状态。若存储也故障，停止新上传，避免持续消耗预占。修复后按租约和幂等规则继续，不批量改为“成功”。

### 7.3 制品与数据恢复

必须切换旧制品时，先进入维护模式，停止业务写入和 worker，确认该制品是否能维护二期一致性。恢复数据库和对象存储使用相匹配的备份点与对象清单；恢复后对账，再重建索引。

不执行删除二期表的破坏性 down migration，不在回滚过程中物理清理文件。回滚可能涉及停机和备份点后的数据损失，应在演练记录中量化；不能承诺一键无损回到一期。

建议初始恢复目标为 RPO ≤ 24 小时、RTO ≤ 4 小时，采用每日数据库与对象清单备份并保护相关对象。它们是部署目标，只有完成实际恢复演练后才能确认达成。

## 8 最低可观测指标

| 指标 | 建议动作阈值 | 处理 |
| --- | --- | --- |
| 最旧待索引任务年龄 | > 30 秒持续 5 分钟 | 检查 worker 和慢查询；界面提示新内容处理中 |
| 提取任务最旧等待时间 | > 5 分钟持续 10 分钟 | 检查解析资源与积压，保持原文件可用 |
| 搜索 P95 | > 800ms 持续 10 分钟 | 检查查询分布、索引和授权联表成本 |
| 上传失败比例 | 15 分钟内 > 5%，样本至少 20 次 | 区分用户校验失败与系统失败，优先排查后者 |
| 清理 DEAD 任务 | 任何新增 | 检查对象权限和容量对账；不要提前释放容量 |
| 容量对账差异 | 非零且超过一次正常同步窗口 | 记录差异来源，受控修正 |

监控阈值是初值，验收目标和生产告警不必完全等同；低流量情况下单个失败也应可查询。日志采用 requestId 关联，避免默认采集正文、完整关键词和下载凭据。

## 9 验收记录模板

正式验收时建立独立记录，填写版本/提交、环境、数据库迁移版本、执行人、测试日期、固定样本版本、通过/失败/跳过数、指标实测值、缺陷链接、恢复演练结果、已知限制和最终结论。

本文件定义门槛与操作方式，不预填测试通过、功能上线或发布成功。
