## 1 验收目标

验证项目封装与用户实际运行的 RustFS 镜像兼容，而不是仅证明某个 S3 mock 可以运行。既有实例部署完成不代表桶、权限、SDK 校验和业务一致性已经通过。

执行 P2-027 前固定镜像摘要、SDK BOM、HTTP 客户端、JDK、endpoint、region、Path Style、校验策略和专用测试桶。记录允许写入的测试前缀，清理仅针对本次创建且已记录的精确 key；不得遍历并清空用户现有桶。

## 2 兼容矩阵

| 编号 | 场景 | 通过条件 | 追踪 |
| --- | --- | --- | --- |
| S3-01 | 已运行镜像与网络地址 | 宿主机/实际容器运行方式可达；9000 与 9001 不混用；版本可复现 | P2-004、026 |
| S3-02 | 应用身份与桶 | 可访问专用桶；其他桶、桶管理操作被拒绝；无匿名读写 | AC13、P2-027 |
| S3-03 | PutObject/HeadObject/GetObject | 中文显示名不进入对象键；对象长度、类型及下载 SHA-256 正确 | AC01 |
| S3-04 | 边界大小 | 0 字节合法文本、1 字节、20MiB；20MiB+1 被应用拒绝且不发布 | AC01、AC03 |
| S3-05 | checksum 与请求编码 | SDK 默认请求在锁定版本可用；SERVER_SHA256 须证明错误摘要被拒绝，否则采用回读校验 | AC01、AC03 |
| S3-06 | 稳定 key 与请求重试 | PUT 响应丢失后核对再恢复；同尝试相同字节，不产生多份业务文件 | AC02、AC15 |
| S3-07 | 流关闭 | 下载成功、解析中断、浏览器断开均释放连接；重复 100 次后池不耗尽 | AC01、AC15 |
| S3-08 | 删除和 HEAD | 删除不存在的精确对象可确认 ABSENT；403、NoSuchBucket 和超时绝不当作成功 | AC14 |
| S3-09 | ListObjectsV2 分页 | 至少 1005 个小对象，完整遍历不重不漏；不透明 token 不改写 | AC15 |
| S3-10 | 桶版本模式 | 从未启用版本控制的测试桶通过；Enabled/Suspended/无法确认时阻止文件写入 | AC14、P2-026 |
| S3-11 | IAM 负例 | 凭据失效和前缀外访问被拒绝；错误不泄漏密钥或真实其他用户元数据 | AC13 |
| S3-12 | 对象已写、数据库失败 | 候选不可下载；attempt 记录可定位；超过窗口后受控补偿 | AC03、AC15 |
| S3-13 | 上传租约丢失 | 旧尝试晚完成不能覆盖已提交的 key；候选各有独立记录 | AC02、AC05 |
| S3-14 | 删除期间下载与提取 | 新请求被数据库状态拒绝；旧处理不能发布正文；不承诺撤回已发送字节 | AC13、AC14 |
| S3-15 | 孤儿和容量对账 | 活动租约及已发布对象不被清理；清理失败仍保留物理空间占用记录 | AC03、AC14 |
| S3-16 | HTTP 契约与 CORS | 二进制 content type 正确；跨源 Idempotency-Key/If-Match 预检通过；浏览器没有 S3 凭据 | AC01、AC13 |
| S3-17 | 备份与对象恢复 | 数据库引用、桶/key、对象摘要一致；缺失对象不被假定可恢复 | P2-024 |

S3-09 的 1005 个对象仅建在专用测试桶或批准的测试前缀，执行结束按清单精确删除。S3-10 中 Enabled/Suspended 的负例使用另建测试桶，不修改当前业务桶。

## 3 封装层测试

单元测试覆盖 endpoint 与 key 校验、错误翻译、有限重试、流关闭、分页 token、敏感字段日志过滤。不要只断言方法调用次数，应验证失败时业务可观察的结果。

真实兼容测试调用锁定版本的 RustFS，可使用独立测试实例或经确认的专用测试桶；本地 fake 只用于故障注入，不能代替 RustFS 的签名、策略与传输校验测试。

AWS SDK 类型隔离可通过静态依赖约束检查：除适配器和测试外，业务包不得 import SDK 类型。ObjectStorage 异常要保留内部诊断信息，但向 File 服务暴露稳定错误类别。

## 4 故障注入与性能口径

在受控测试环境模拟连接中断、读超时、503、磁盘不足、上传响应丢失、数据库回滚和 worker 失去租约。不要通过破坏用户运行实例数据目录来模拟故障。

性能拆分记录浏览器接收时间、临时落盘时间、PUT、HEAD、完整性核对、数据库发布与下载时间。READBACK_SHA256 多一次对象读取，必须计入“上传确认”时间，不能只报告 PUT 耗时。

建议记录 1KiB、5MiB、20MiB，单上传与每实例 4 并发；报告 P50/P95、临时目录峰值、连接数和堆占用。二期文件正文可搜的 60 秒目标仍从接收成功且发布为 STORED 后计算，不能隐藏发布前上传确认耗时。

## 5 通过门槛

S3-01 至 S3-17 必须给出结果和证据；权限、字节不一致、错误删除和已删除文件重新可访问均为发布阻塞。checksum 不兼容时可以采用已验证的 READBACK_SHA256，不可只忽略相关异常。

常规健康探针仅做读取检查；验收才创建指定的测试对象。密钥、签名和正文不进入报告。运行时未验证的功能标为未验证，不写成“RustFS 全部兼容”。

## 6 验收记录模板

| 字段 | 待填写内容 |
| --- | --- |
| RustFS 镜像 | 容器 image ID、RepoDigest、可确认的版本 |
| 应用环境 | 提交标识、JDK、Spring Boot、OS、容器资源 |
| SDK | AWS SDK BOM 与 HTTP 客户端版本 |
| 接入参数 | endpoint 脱敏值、region、Path Style、桶名、校验策略 |
| 权限 | 应用身份名称和策略摘要，不含 AK/SK 明文 |
| 对象行为 | PUT/GET/HEAD/DELETE/list/桶版本检查结果 |
| 执行记录 | 时间、执行人、用例通过/失败/跳过及证据 |
| 性能与恢复 | 延迟、内存/临时磁盘峰值、失败恢复结果 |
| 结论 | 可接入 / 需修复；具体版本边界与已知限制 |

兼容结果对应具体镜像和 SDK 组合。任何一方升级后，至少重跑签名、校验、流关闭、权限、删除与恢复用例。
