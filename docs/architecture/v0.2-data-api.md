更新日期：2026-09-18  
状态：建议契约，实施时同步生成 OpenAPI；本文不代表接口已上线

[二期总览](../product/v0.2-plan.md) · [业务规则](../product/v0.2-requirements.md) · [技术架构](v0.2-architecture.md) · [S3 存储契约](v0.2-s3-storage.md)

## 1 兼容约定

- 沿用 `/api/v1`、现有 Bearer Token、默认 Workspace 解析、UUIDv7、UTC 时间和 ISO-8601 输出。
- 成功直接返回资源，失败沿用 `code/message/details/requestId`；无响应体操作用 204。
- 普通列表复用 `items/page/size/total/totalPages`，页码从 1 开始，默认 size=20，最大 100。
- 时间区间采用 `updatedFrom` 包含起点、`updatedTo` 不含终点，前端按 Workspace 时区转换为 UTC。
- 客户端不提交可信的 workspaceId、createdBy、对象存储键或已用容量。
- metadata 的 `version`、标签集合的 `tagVersion`、文件内容的 `contentVersion`、处理任务的 `extractionGeneration` 分别有用途，不能互相替代。
- 所有新结构通过新增 Flyway 迁移引入，不修改已执行的 V1 至 V5；具体新版本号在实施时根据最新迁移尾号分配。

## 2 数据模型

以下描述字段及约束，不提供可直接执行的迁移 SQL，避免规划阶段误改现有数据库。

### 2.1 files

| 字段组 | 主要字段及含义 |
| --- | --- |
| 标识 | id、workspace_id、project_id 可空、created_by |
| 展示 | display_name、original_name、detected_media_type、extension |
| 内容 | size_bytes、sha256、storage_provider、storage_profile_id、storage_bucket、object_key、storage_etag、storage_version_id、content_version |
| 生命周期 | state、deleted_at、deletion_reason、purge_after、purged_at |
| 处理 | extraction_status、extraction_generation、extraction_error_code、extraction_retryable |
| 并发和时间 | version、tag_version、created_at、updated_at |

state 为 UPLOADING / STORED / FAILED / DELETED / PURGED。content_version 首版固定为 1，内容不可覆盖；version 随用户可见元数据及生命周期变化递增。后台提取状态可独立更新 generation，不制造重命名的无意义版本冲突。

storage_provider 为 S3，storage_profile_id 选择已配置 RustFS 实例，storage_bucket 与 object_key 固定保存实际对象位置；配置默认桶变更不能重解释旧文件。storage_etag 不作为 SHA-256；storage_version_id 在 P0 从未启用版本控制的专用桶中为空。这些字段仅供服务端使用，不进入普通 File DTO。

`(workspace_id,id)` 唯一；`(storage_profile_id,storage_bucket,object_key)` 对已分配对象引用唯一且不可接受客户端覆盖。project_id 使用 `(workspace_id,project_id)` 复合外键引用项目，项目表补充相应唯一键。size_bytes 非负，STORED 必须具有完整对象引用和校验摘要。

建议索引：活动文件 `(workspace_id,updated_at DESC,id)`、项目文件 `(workspace_id,project_id,updated_at DESC,id)`、回收站 `(workspace_id,deleted_at DESC,id)`、到期清理 `(state,purge_after)`。按查询计划验证，不无条件堆叠索引。

### 2.2 file_uploads 与 workspace_storage_usage

`file_uploads` 保存 id、workspace_id、file_id、idempotency_key、request_fingerprint、declared_size、reserved_bytes、state、current_attempt_id、lease_token、lease_until、expires_at、created_at、completed_at、error_code。唯一约束为 `(workspace_id,idempotency_key)` 和 file_id。

state 为 CREATED / RECEIVING / VERIFYING / COMPLETED / FAILED / EXPIRED；VERIFYING 表示字节已接收，正在写入和核对 RustFS，尚不可下载。相同幂等键、相同创建参数返回同一会话；不同参数返回 409。过期会话不能复活，用户重新提交时使用新键。

`file_upload_attempts` 每个尝试一行：id、workspace_id、upload_id、storage_profile_id、storage_bucket、object_key、lease_token、size_bytes、sha256、state、created_at、verified_at、cleanup_after、last_error_code。尝试 ID 和对象引用唯一，同 Workspace 外键指向上传会话；记录在发出 PUT 前提交。state 至少区分 ALLOCATED、PUTTING、VERIFIED、COMMITTED、ORPHANED、CLEANED、FAILED；PUTTING 超时的实际写入结果未知，必须 HEAD/核对而非直接判为空。该表保留历次候选，不能只覆盖 current_attempt_id 后丢失旧对象。它不保存凭据或将宿主临时路径暴露给浏览器。

`workspace_storage_usage` 每个 Workspace 一行：quota_bytes、used_bytes、reserved_bytes、version、updated_at。接收成功将同一预占转为已用，失败或过期释放预占，文件物理清理成功后减少已用。并发更新使用行锁或条件更新，禁止先读后无条件累加。

每日对账数据库状态与对象存在性，修正须可审计；清理只针对已确认超过有效期且无业务引用的对象。上传中的临时目录有独立最大占用限制，不能靠业务容量计数代替磁盘容量保护。

### 2.3 file_extractions

字段：workspace_id、file_id、content_version、extraction_generation、parser_version、status、text_content、text_length、truncated、error_code、started_at、finished_at。

每次处理代次唯一；只有与 files 当前有效代次匹配的 READY 内容参与索引。text_content 最多 200000 字符，truncated 明确表示超过检索范围。EMPTY 和 SKIPPED 不伪造正文。后续如果需要页面、分块或 RAG 引用，可以另加结构，不在二期假装已经具备精确页码定位。

### 2.4 tags 与对象标签关系

`tags`：id、workspace_id、name、normalized_name、color、version、created_at、updated_at。唯一约束 `(workspace_id,normalized_name)`；颜色保存语义枚举，不能任意注入 CSS。

建立 `project_tags`、`task_tags`、`note_tags`、`file_tags` 四张关系表：workspace_id、source_id、tag_id、created_at。主键 `(workspace_id,source_id,tag_id)`，分别使用复合外键指向对象和标签。相比只有 `entity_type + entity_id` 的多态表，这一方案可以让数据库校验对象确实存在且同 Workspace。

Project、Task、Note 新增 `tag_version BIGINT NOT NULL DEFAULT 0`；File 建表时包含此字段。标签集合替换通过 tagVersion 比较并原子递增，不变更对象正文版本。删除标签时解除关联并递增受影响对象的 tagVersion，防止其他客户端用旧集合重新写回已删除 ID。

标签删除采用事务硬删除定义及关系；用户可再次创建同名标签，但产生新的 ID，不自动恢复旧关联。标签列表引用计数仅统计当前可读取的未删除对象，包含归档对象，并在 UI 标注口径。

### 2.5 task_files 与 note_files

字段：workspace_id、task_id 或 note_id、file_id、created_at、created_by。主键为 Workspace、目标 ID、file_id 的组合，复合外键确保同 Workspace。项目归属相同、目标有效且可写由事务内锁定源对象和文件后检查。

直接软删除文件时保留关系供恢复；删除任务/笔记时清理关系；物理清理文件时移除全部关系。项目文件列表直接查 files.project_id，不新增 project_files 多对多关系。

### 2.6 background_jobs

字段：id、workspace_id、job_type、source_type、source_id、source_version、generation、dedupe_key、status、attempts、next_run_at、lease_token、lease_until、error_code、created_at、updated_at。

类型至少包括 EXTRACT_FILE、UPSERT_SEARCH、REMOVE_SEARCH、PURGE_FILE。状态为 PENDING / RUNNING / SUCCEEDED / DEAD。dedupe_key 唯一，就绪查询索引覆盖 status 与 next_run_at；租约回收查询索引覆盖 status 与 lease_until。已完成任务可按保留策略压缩清理，不能先删除唯一的待处理事实。

### 2.7 search_documents

字段：index_generation、workspace_id、source_type、source_id、source_version、extraction_generation、title、body_text、normalized_title、normalized_body、search_bigrams、source_updated_at、indexed_at。

唯一键 `(index_generation,workspace_id,source_type,source_id)`。GIN 建于 search_bigrams，B-tree 建于当前代次、Workspace、类型和时间查询所需组合。可选 pg_trgm 索引按第一周评估决定，不列为默认依赖。

source_type 为 PROJECT / TASK / NOTE / FILE。投影只保存检索必要数据；标签名、访问权和父项目生命周期不以缓存副本作为最终依据。对 index_generation 的读切换由运维配置控制，未回填完成不能切换。

## 3 文件 API

| 方法与路径 | 输入要点 | 返回与语义 |
| --- | --- | --- |
| GET `/files/capabilities` | 无 | 格式、大小/数量限制、容量和支持的预览/提取能力 |
| POST `/files/uploads` | Idempotency-Key；name、size、mediaType、projectId | 201 新会话；200 同参数重试；返回 uploadId、fileId、expiresAt、contentPath |
| PUT `/files/uploads/{uploadId}/content` | 原始文件字节；Authorization；声明的 Content-Type | 201 接收完成的 File；200 已完成重试；不允许覆盖 |
| GET `/files/uploads/{uploadId}` | 无 | 会话状态及关联文件 ID，用于刷新后确认结果 |
| GET `/files` | q、projectId、tagIds、tagMode、mediaTypes、extractionStatus、updatedFrom、updatedTo、uncategorized、includeArchived、view、page、size、sort | 分页 FileSummary；view 默认 active，可为 trash |
| GET `/files/{id}` | 无 | FileDetail，包括标签、引用、能力和处理状态；本 Workspace 删除态可供回收站详情读取 |
| PATCH `/files/{id}` | version、displayName 和/或 projectId | 更新元数据；有引用时禁止改项目 |
| GET `/files/{id}/content` | disposition=attachment 或 inline | 授权后返回二进制，默认 attachment，限制允许 inline 的类型 |
| GET `/files/{id}/text` | 无 | 当前提取文本、truncated、status；非 READY 时返回状态而非伪造文本 |
| POST `/files/{id}/extraction-retries` | 无 | 202 新处理代次；冷却/已有任务返回冲突或限流 |
| DELETE `/files/{id}` | If-Match 携带 metadata version | 204 软删除；已删除且可见时幂等成功 |
| POST `/files/{id}/restore` | version | 200 File；超过保留期、父级无效或归档时拒绝 |

路径表均省略公共前缀 `/api/v1`。静态路径 uploads、capabilities 须与 `{id}` 路由明确区分。contentPath 是同源应用 API 路径，不是对象存储地址。

文件列表 uncategorized=true 表示 project_id 为空且不存在任何标签关系，必须由服务端过滤。includeArchived 默认 false，活动列表排除归档项目所属文件；设为 true 后可读但不可写。trash 视图按文件删除态检索，不因父项目已删除而隐藏回收站条目；只允许查看元数据和规则允许的恢复操作。与未分类互相矛盾的项目/标签条件直接返回空结果，不静默丢弃筛选。

文件列表 q 仅对显示名称做字面包含查询，允许 1 至 100 字符，与全局正文搜索的最短 2 字符语义分开。默认 sort=updatedAt,desc，可选 name,asc、sizeBytes,desc；任何其他排序值返回校验错误，不直接拼接 SQL 字段。时间条件采用本文件第 1 节约定。

文件元数据示例：

```json
{
  "id": "01995000-0000-7000-8000-000000000001",
  "displayName": "缓存方案.pdf",
  "originalName": "缓存方案.pdf",
  "mediaType": "application/pdf",
  "sizeBytes": 481920,
  "projectId": null,
  "state": "STORED",
  "extraction": { "status": "READY", "truncated": false, "retryable": false },
  "version": 1,
  "tagVersion": 0,
  "tags": [],
  "capabilities": { "canEdit": true, "canDownload": true, "canRestore": false }
}
```

capabilities 便于显示操作，服务端仍逐次鉴权。完整响应还须包含 createdAt、updatedAt；示例仅展示核心字段。删除文件详情可读只限当前 Workspace 的回收站操作；content 和 text 始终要求 STORED。

## 4 附件 API

| 方法与路径 | 语义 |
| --- | --- |
| GET `/tasks/{taskId}/files` | 分页返回关联文件及 deleted 标记；不返回已删文件正文 |
| PUT `/tasks/{taskId}/files/{fileId}` | 幂等挂载，成功 204 |
| DELETE `/tasks/{taskId}/files/{fileId}` | 幂等解绑，成功 204 |
| GET `/notes/{noteId}/files` | 同任务附件规则 |
| PUT `/notes/{noteId}/files/{fileId}` | 同任务附件规则 |
| DELETE `/notes/{noteId}/files/{fileId}` | 同任务附件规则 |

PUT/DELETE 先确认目标可见且可写，再确认文件范围。目标已删除或不属于当前 Workspace 时仍为 404，不能因为操作是幂等就绕过授权。重复解绑一个已经不存在的关联返回 204，不影响其他关联。

## 5 标签 API

| 方法与路径 | 语义 |
| --- | --- |
| GET `/tags` | q、page、size；返回定义及授权后的引用计数 |
| POST `/tags` | name、color；201 Tag |
| PATCH `/tags/{id}` | name/color、version；200 Tag |
| DELETE `/tags/{id}` | If-Match；204，解除全部关联但保留对象 |
| GET `/{resource}/{id}/tags` | resource 仅 projects/tasks/notes/files；返回 tags 与 tagVersion |
| PUT `/{resource}/{id}/tags` | tagIds 完整集合、tagVersion；原子替换，返回新集合和版本 |

空 tagIds 表示清空。请求中的重复 ID 先去重再检查数量；任何一个 ID 非法或跨范围，整笔替换失败。来源对象不存在返回 404；已归档来源返回 409 PROJECT_ARCHIVED 或 RESOURCE_READ_ONLY。

## 6 搜索 API

`GET /api/v1/search` 参数：

| 参数 | 约定 |
| --- | --- |
| q | 可空；最多 100 字符，最多 8 个查询项，每项至少 2 字符 |
| types | 重复参数或 OpenAPI 声明的数组格式；值为 PROJECT/TASK/NOTE/FILE |
| projectId | 可空；限制某项目，包括项目自身及直接归属的其他对象 |
| tagIds / tagMode | 标签 ID 数组；ALL 默认，ANY 可选 |
| updatedFrom / updatedTo | UTC ISO-8601，起点包含，终点不包含 |
| includeArchived | 默认 false；绝不包含已删除内容 |
| sort | relevance 默认；updatedAt,desc 可选 |
| page / size | 1 至 100 页；size 1 至 100，默认 20 |

无 q 且无有效筛选时返回空 items 并设置 `meta.emptyQuery=true`，不触发全库结果统计。仅 includeArchived=true 不算有效筛选。无结果的正常查询 total=0；超时或故障使用错误响应。

```json
{
  "items": [
    {
      "type": "NOTE",
      "id": "01995000-0000-7000-8000-000000000002",
      "title": "缓存方案讨论",
      "project": null,
      "tags": [],
      "snippet": [
        { "text": "本次", "matched": false },
        { "text": "缓存", "matched": true },
        { "text": "调整采用分级过期。", "matched": false }
      ],
      "matchedFields": ["TITLE", "BODY"],
      "archived": false,
      "updatedAt": "2026-09-18T02:00:00Z"
    }
  ],
  "page": 1,
  "size": 20,
  "total": 1,
  "totalPages": 1,
  "meta": { "emptyQuery": false, "indexingPending": false, "tookMs": 48 }
}
```

示例耗时不是实测。前端根据 type/id 使用现有路由映射，不接受索引中的任意外链。indexingPending 表示当前 Workspace 有相关积压，不承诺搜索快照完整；删除和授权仍实时生效。

搜索 items 和 total 在同一数据库快照完成匹配与授权。单次响应一致，跨页期间发生编辑可使排序变化；P0 不承诺冻结式分页快照。`totalPages` 是理论页数，超过 100 时 UI 提示缩小范围，不能继续请求被禁止的页码。

## 7 错误码与客户端处理

| HTTP | code | UI 行为 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR / SEARCH_QUERY_INVALID | 指出字段和有效范围，保留输入 |
| 401 | UNAUTHORIZED | 沿用一期会话恢复，失败再登录 |
| 404 | RESOURCE_NOT_FOUND | 统一不可见，不泄漏其他 Workspace 的对象信息 |
| 409 | VERSION_CONFLICT / TAG_VERSION_CONFLICT | 保留当前内容，提示刷新核对 |
| 409 | TAG_NAME_CONFLICT | 提供选择已有标签的入口 |
| 409 | PROJECT_ARCHIVED / RESOURCE_READ_ONLY | 提示只读来源，停止写入 |
| 409 | FILE_SCOPE_CONFLICT / FILE_HAS_REFERENCES | 说明归属冲突或先解绑操作 |
| 409 | UPLOAD_STATE_CONFLICT / IDEMPOTENCY_CONFLICT | 查询原会话或重新发起，禁止静默覆盖 |
| 409 | STORAGE_QUOTA_EXCEEDED | 展示容量，说明回收站也占用 |
| 413 | FILE_TOO_LARGE | 明确单文件大小限制 |
| 415 | FILE_TYPE_NOT_ALLOWED | 展示支持的格式 |
| 429 | RATE_LIMITED | 显示等待提示，遵守 Retry-After |
| 503 | FILE_STORAGE_UNAVAILABLE / FILE_CONTENT_UNAVAILABLE / SEARCH_UNAVAILABLE | 保留状态，允许重试，不显示成功或空结果；已授权文件原对象缺失时触发内部对账 |
| 502 | FILE_INTEGRITY_CHECK_FAILED | 文件长度或摘要不一致，不发布候选；保留上传结果供排查 |

解析失败通常体现在已创建 File 的 extraction 对象中，不将后台错误伪装成上传接口失败。建议 errorCode 包含 PASSWORD_PROTECTED、INVALID_DOCUMENT、PARSE_TIMEOUT、RESOURCE_LIMIT、NO_TEXT；用户只看到可理解说明，内部堆栈进入受控日志。

## 8 迁移和兼容检查

迁移按“增加基础表和复合唯一键 → 标签和附件关系 → 任务和投影 → 回填”分批实施。既有 API 增加标签响应字段时保证默认空列表和 tagVersion=0，旧请求仍能使用；附件移动约束属于新增业务行为，需要更新一期任务/笔记编辑说明和回归用例。

当前 jOOQ 使用 DDLDatabase 从迁移脚本生成结构。任何 PostgreSQL 数组、扩展或特殊索引语法都必须验证生成链路；不能为解决代码生成而移除生产需要的约束。数据库集成测试使用真实 PostgreSQL 16；模型变化同步 Scalar 文档和示例。
