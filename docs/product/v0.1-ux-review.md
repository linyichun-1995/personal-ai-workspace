# V0.1 交互复盘与改进

日期：2026-09-15

[文档索引](../README.md) · [一期规划](v0.1-plan.md) · [前端开发说明](../development/frontend.md)

## 本轮目标

用户反馈的优先问题是“整体入口太多、下一步不清楚”。本轮围绕已有的项目、任务、笔记和概览完成交互改进，复用现有后端 API。

核心判断：此前页面同时承载未来能力、展示性指标和业务操作，用户很难区分可用入口，也不容易判断现在应该做什么。改进重点是减少选择、明确主操作、保留工作上下文和输入内容。

## 主要问题与已做改动

| 问题 | 调整后的行为 |
| --- | --- |
| 主导航层级较多，混有未开放模块 | 主导航集中为概览、项目、任务、笔记；状态视图放在所属页面内 |
| 顶部文案暗示全局内容搜索和 AI，实际仅跳转页面 | 改为快捷导航，创建入口绑定实际动作；使用标准对话框管理键盘焦点 |
| 概览同时出现无效周期选择、后续 AI 指标和重复模块 | 展示四项真实指标、逾期提醒，以及今日任务、项目、未来安排和最近笔记 |
| 新建项目后缺少明确下一步，详情默认是信息统计 | 创建成功进入任务分区，空项目直接提供“添加第一个任务” |
| 任务行出现两套复选框、原始 ID 和含义不明的更多按钮 | 保留完成复选框，提供可点击标题、明确编辑按钮和行内状态选择 |
| 已取消任务被显示成待处理，紧急优先级被合并成高 | 直接展示后端状态与优先级枚举；增加逾期视图入口 |
| 任务详情难以从概览定位 | 通过 `taskId` 路由参数直接打开指定任务，并按需加载详情 |
| 项目和笔记列表只展示固定一页 | 列表和项目内的任务、笔记均可翻页；全部任务支持继续加载，明确搜索范围 |
| 从详情返回列表后，分区、搜索条件和页码丢失 | 项目列表页码、笔记分区与关键词写入地址；详情返回时恢复来源；项目内分区与分页同样保留 |
| 表单关闭与重复提交容易丢失内容或重复创建 | 取消、浏览器返回和离开页面均保护未保存输入；提交期间禁用输入；保存成功后正常退出并重置表单 |
| 归档项目仍能触发任务编辑，随后才收到错误 | 归档项目禁用任务修改，关联笔记显示只读说明与返回项目入口 |
| 笔记保存可能重叠，保存标签可能领先于最新输入 | 自动保存按顺序执行，继续处理请求期间的新输入；全部成功后才显示已保存 |
| 笔记离开、错误恢复和上下文返回不清楚 | 页面内离开先尝试保存；错误保留输入并支持重试、复制；从项目进入时优先返回原项目笔记分区，从笔记列表进入时恢复原筛选 |
| 笔记归档视图使用反向按钮，不易识别当前分区 | 使用全部、收藏、归档三个明确分区，区分无内容与无搜索结果 |
| 删除确认立即关闭，用户无法判断是否完成 | 删除请求期间保留对话框并显示处理状态，成功后退出 |

## 调整后的核心路径

1. **开始工作**：概览 → 优先处理逾期或今日任务 → 直接打开任务或勾选完成。
2. **推进目标**：创建项目 → 添加第一条任务 → 设置状态与截止时间 → 持续推进。
3. **整理上下文**：项目笔记 → 编辑与自动保存 → 返回所属项目；零散记录从笔记入口直接新建。
4. **回顾工作**：已完成任务、归档项目和收藏笔记都在对应业务页面内查找。

### 列表与返回规则

- 项目和笔记每页 20 条；删除或归档导致当前页没有内容时，提供返回第一页的入口。
- 项目内任务按创建时间倒序排列。添加成功回到第一页，刚创建的任务能直接看到；本页任务搜索与排序仅针对当前页。
- 项目内笔记按更新时间倒序排列，打开笔记后能回到原分区和页码。
- 笔记列表搜索请求延迟 300ms 合并连续输入，地址保留关键词、收藏/归档分区和页码；翻页不丢失筛选。
- 离开未保存的任务或项目表单时，可以继续编辑或放弃；请求处理期间保留当前操作，保存成功后的跳转不会被误拦截。

## 范围与实现边界

本轮没有新增后端业务接口、数据库迁移或依赖包。AI、文件、集成、模板等后续能力未实现，其原有占位路由保留，但不再占用主导航和概览。

本轮不代表 V0.1 规划中所有待办均已完成。看板、拖动排序、完整子任务交互等仍需按后续优先级单独推进。全部任务搜索覆盖已加载的数据，项目内任务搜索覆盖当前页；笔记草稿仅保留在当前页面内存，版本冲突需要复制内容后重新打开核对。

## 检查方式

本轮按用户要求不运行测试。使用 TypeScript 类型检查、改动文件的 lint 和格式检查，核对路由与既有 API 的参数约定。未进行浏览器运行验证，运行时表现仍需实际使用确认。
