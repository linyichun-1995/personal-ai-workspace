## 1 使用方法

P2 前缀表示二期任务编号，与功能优先级 P0/P1 无关。P2-001 至 P2-027 为本期 P0；P2-026/027 是补充 RustFS S3 封装后新增的任务，原编号保持稳定。P2-101 之后为后续增强。负责人使用角色名，不假设已有实际人员承诺。

每项任务进入开发前补充执行人、预计起止、关联提交和验收证据。状态统一为待开始、进行中、待联调、待验收、已完成、阻塞。阻塞须记录具体依赖和下一步，不能以“开发完成”代替端到端验收。

人日表示一个人约一个正常工作日的有效投入，是粗估而非报价。基准包含实现者必要的自检；专门测试任务负责跨模块、异常和系统性回归，避免把同一测试工作重复计数。

## 10 每项任务的完成定义

任务须同时具备：范围内实现、必要自检、关联接口文档、错误状态、权限与生命周期校验、对应 AC 的验证证据。后台任务还需给出重复执行和失败恢复证据；界面任务还需验证键盘、空状态、失败和返回上下文。

建议执行记录：`任务 ID / 执行人 / 状态 / 实际人日 / 关联变更 / AC 证据 / 遗留问题 / 完成日期`。记录在任务系统或后续 Markdown 执行日志中，不将本规划表预填为已完成。
