# V0.2 产品需求与业务规则

更新日期：2026-09-18  
状态：二期建议需求基线

[二期总览](v0.2-plan.md) · [任务清单](v0.2-backlog.md) · [交互设计](../design/v0.2-interaction.md)

## 1 使用对象与范围

主要用户是已经使用一期管理个人项目、任务和笔记的人。二期继续使用当前默认 Workspace，不增加多人邀请、Workspace 切换或对象级权限。访问规则从服务端当前用户及成员关系推导，客户端不能通过传入 Workspace ID 获得权限。

下列 R01 至 R08 均为 P0 需求，任务和测试以这些编号追踪。本文参数为建议初始值；配置调整不能降低隔离和数据完整性要求。

## 2 R01 文件资料库

### 2.1 收集与管理

用户可从文件页、项目文件分区或任务/笔记附件区选择文件，也可在上传区域拖放。每个文件单独显示状态，部分失败不阻止其他文件完成。上传前展示格式、单文件限制和剩余容量。

原文件统一使用用户已运行的 RustFS，通过后端二次封装的 S3 接口访问。浏览器继续使用工作台文件 API；桶名、存储键和 S3 凭据不进入用户操作流程。接入范围见 [S3 封装方案](../architecture/v0.2-s3-storage.md)。

首版支持 PDF、DOCX、TXT、MD、PNG、JPEG、WebP。服务端根据扩展名、声明类型、内容识别结果综合校验；文本文件按可接受文本内容验证，不能把“没有固定魔数”误判为非法。禁止 SVG、HTML、脚本、可执行文件、压缩包和带宏 Office 文件。

| 参数 | 初始规则 |
| --- | --- |
| 单文件 | 20MiB，即 20971520 字节 |
| 单次选择 | 最多 10 个；客户端最多并发上传 2 个 |
| 工作空间容量 | 1GiB；活动文件、回收站文件和上传预占量合计计算 |
| 文件显示名称 | 1 至 200 个 Unicode 字符，去除首尾空格，拒绝路径控制字符 |
| 单次接收有效期 | 上传会话 1 小时；超时释放预占容量并清理临时对象 |
| 重复文件 | 同名允许；不覆盖旧文件；同一提交重试使用幂等键 |
| 文件内容 | 上传后不可原位覆盖；重新上传产生新文件 ID |

列表支持名称查询、项目、标签、文件类型、处理状态和更新时间筛选，默认每页 20 条，按更新时间倒序。默认隐藏归档项目文件，可通过“包含归档”读取；回收站独立列出删除态文件。文件详情显示名称、大小、类型、归属、标签、引用位置、上传时间和处理结果。

支持重命名、选择项目归属、软删除和恢复。重命名只改变展示名称，不改变原始文件名、文件格式和对象键。文件存在附件引用时不能改项目，须先解除引用；不能归入已归档或已删除项目。

### 2.2 下载与预览

下载每次都校验当前授权、删除状态和文件可用状态。TXT/MD 以纯文本预览，图片预览经过安全解码的显示内容；PDF 可使用受限浏览器预览，浏览器不支持时显示下载操作。DOCX 首版提供提取文本预览与原文件下载，不承诺还原 Word 排版。

文件预览失败时保留元数据和下载入口；文件仍在接收时不能下载。预览不执行 Markdown 中的 HTML、Office 宏、外部资源抓取或文档脚本。

### 2.3 验收结果

- **AC01**：上传合法文件并通过 RustFS 写入和完整性核对后，列表和详情可见；刷新页面仍能读取处理状态；下载字节摘要与接收成功的原文件一致。传输到 100% 但仍在 VERIFYING 时不得显示为已经保存成功。
- **AC02**：同一幂等提交不会产生多份文件或重复占用容量；同名不同提交不会互相覆盖。
- **AC03**：超限、伪装类型、配额不足和网络失败都有可操作反馈，失败不会留下永久预占。

## 3 R02 文本提取与处理状态

PDF、DOCX、TXT、MD 支持提取可搜索文本。TXT/MD 首版接受 UTF-8 和 UTF-8 BOM，编码不符提示转换后重新上传；零字节文本可保存为 EMPTY，零字节 PDF/DOCX 因格式无效拒绝。PNG、JPEG、WebP 仅搜索文件名；扫描 PDF、图片 OCR、加密文件解密和完整 Office 转码不纳入首版。

上传和文本提取使用两组独立状态。文件保存成功后即进入可管理状态；提取排队、失败或无文本时仍可按名称搜索、下载原文件。界面不以一个含糊的“失败”同时代表传输失败和解析失败。

| 处理情况 | 用户文案与操作 |
| --- | --- |
| QUEUED / PROCESSING | 正在处理正文；可按名称查找和下载 |
| READY | 正文可搜索；超出上限时另显示“仅检索前 200000 字符” |
| EMPTY | 未提取到文本，扫描件暂不支持正文搜索 |
| SKIPPED | 此格式仅支持名称搜索 |
| FAILED 且可重试 | 展示简短原因和“重新处理” |
| FAILED 且不可重试 | 展示加密、损坏等原因，建议上传可读取版本 |

单次处理初始限制：30 秒、子进程堆上限 256MiB、解包总量 100MiB、条目数 1000、文本输出 200000 字符；不递归处理嵌入附件。隔离进程的总内存另设上限，不能把 Java 堆限制当作整个容器限制。具体版本与实测资源在第一周固定。

暂时性失败单个任务最多执行 3 次，包含首次；永久失败不自动重试。用户手动重新处理须满足 60 秒冷却且不存在活动任务，产生新的处理代次。删除文件后，旧处理结果不得再次发布。

- **AC04**：固定样本集覆盖文本 PDF、扫描 PDF、中文 DOCX、空文本、损坏和加密文件，状态与说明正确。
- **AC05**：后台处理中重启服务、重复投递或删除文件，不导致主服务崩溃、重复正文或已删文件重新可搜。

## 4 R03 项目任务笔记的附件

文件首先属于 Workspace，可选归属一个 Project。项目文件分区列出直接归属该项目的文件，不通过文件名推断归属。任务和笔记各有附件关联表，可以引用多个文件；同一文件可被同范围内多个对象引用。

范围规则是 `file.projectId` 与 `target.projectId` 相同，包括两者都为空。不能把项目 A 的资料直接挂到项目 B。附件是现有内容的辅助区域，不将 Note 增加 Task 关联作为前置条件。

从任务或笔记上传时继承其项目，但“创建文件”和“建立附件关系”是可区分的两步。第二步失败时，原文件留在对应文件列表，提示用户重试关联，不静默删除已上传资料。

移除附件只解绑；删除文件会让所有引用位置显示“文件已删除”且不可下载。恢复文件时，目标仍有效且范围一致的引用可重新显示。删除任务或笔记只清理其附件关系，不删除原文件。移动带附件的任务/笔记到其他项目时，首版拒绝并提示先解除附件，防止一期编辑入口绕过范围约束。

- **AC06**：在项目、任务和笔记中上传或选择同范围文件，引用数量正确；解绑不删除原文件。
- **AC07**：跨范围挂载、对象移动和归档只读均由服务端限制；返回来源时保留项目分区、列表条件和页码。

## 5 R04 统一标签

Project、Task、Note、File 共用 Workspace 内的标签集合。标签具有稳定 ID、名称和有限颜色选项；选择器支持输入过滤、键盘选择和就地创建。管理入口位于设置的标签分区。

标签名称在 NFKC 规范化、首尾去空白及大小写折叠后按 Workspace 唯一；显示保留用户名称。长度 1 至 30 个 Unicode 字符，支持中文和名称内空格；控制字符和空名称非法。此规则是项目产品选择，不照搬正文标签语法。

每个对象最多 20 个标签，每个 Workspace 最多 500 个活动标签。用户可添加、移除、重命名、更改颜色和删除标签。删除标签前显示受影响对象数量；确认后仅解除关联，不删除对象。全局重命名和删除可影响归档对象的标签显示，视为分类维护；归档对象自身的标签集合不允许编辑。

标签替换接口使用对象独立的标签版本号，避免覆盖另一处的并发修改，也不让标签操作造成笔记正文自动保存的无意义冲突。标签同名创建竞争返回明确冲突，并允许选择已存在标签。

多标签筛选默认“同时具备全部标签”；高级筛选可切换“具备任意标签”，URL 与 API 均显式记录模式。点击标签默认进入全局搜索的该标签视图，空关键词合法。

- **AC08**：四类对象使用同一标签 ID；重命名立即反映在各处；删除标签后对象保持存在。
- **AC09**：大小写/全半角同名、数量限制、并发替换和跨 Workspace 标签注入均按规则处理。

## 6 R05 全局关键词搜索

### 6.1 检索范围

| 对象 | 可搜索内容 | 来源操作 |
| --- | --- | --- |
| Project | 名称、描述 | 打开项目详情 |
| Task | 标题、描述 | 打开现有任务详情或编辑入口 |
| Note | 标题、Markdown 可见文本，包括代码块文本 | 打开笔记；不要求精准滚动定位 |
| File | 显示名称、已成功提取的正文 | 打开文件详情；展示命中片段 |

标签通过筛选关联表参与检索，不将标签名字当正文重复索引。隐藏 URL、Markdown HTML、图片像素、PDF 扫描图和 Office 内嵌附件不承诺检索。

默认排除删除对象、归档项目及其任务/笔记/文件，以及独立归档笔记。选择“包含归档”后展示仍有读取权限的归档数据，明确只读状态。已完成和已取消任务保留可搜，不与删除混同。

### 6.2 查询语义

- q 最长 100 个 Unicode 字符，规范化后按空白分为最多 8 项；每项至少 2 字符。一个字或字母提示继续输入；不静默搜索全部正文。
- 各项采用字面包含匹配，项之间 AND；各项可分别命中标题或正文。无正则、布尔表达式、引号短语语法、拼音或同义词承诺。
- `%`、`_`、反斜杠等均作为普通文字处理，不扩大 SQL 匹配范围。
- q 为空且有筛选时允许浏览；q 为空且无筛选时显示搜索提示，不执行全库正文检索。
- 支持对象类型、项目、标签及匹配模式、更新时间区间、是否包含归档；各筛选类别之间 AND，多个对象类型之间 OR。
- 排序支持相关性、更新时间倒序。相关性优先标题完整匹配、标题前缀、标题包含、正文命中，再按更新时间和稳定 ID 决定顺序。
- 每页默认 20 条、最大 100 条；最大浏览 100 页，继续缩小条件后重查。结果含总数、类型、标题、项目、标签、命中片段、更新时间和来源标识。

结果摘要最多 240 字符，先取真实命中位置附近文本，再输出安全文本片段。高亮不能直接注入用户内容为 HTML。中文、英文和中英文混合的规范化及定位需使用同一约定，不能按字符数猜原文偏移。

### 6.3 新鲜度与失败

搜索索引异步更新。普通业务变更目标 5 秒内可见；新文件正文以处理状态为准。索引积压时展示“部分新内容仍在处理中”；请求超时展示失败及缩小条件操作，不把未执行成功显示为“0 条结果”。

旧局部查询保持独立语义。任务表若仍只搜索当前已加载数据，必须明确写“筛选已加载任务”，并提供全局检索当前类型的入口。全局结果不能退化为前端对已加载列表过滤。

- **AC10**：同一关键词能找到四类对象及文件正文；两字中文、大小写和特殊字符用例通过。
- **AC11**：项目、标签 ALL/ANY、归档、分页、排序和总数遵循同一授权与匹配条件。
- **AC12**：从搜索打开来源，再返回时还原查询、筛选、页码；失败和处理中均不伪装成无结果。

## 7 R06 权限与生命周期

| 动作 | 规则 |
| --- | --- |
| 非本 Workspace 的 ID | 文件、标签、附件、搜索来源均按不可见返回，不泄漏名称或数量 |
| 归档项目 | 可读取和下载；项目范围内新增、编辑、挂载、删除、手动重试均禁用 |
| 直接删除文件 | 进入文件回收站；搜索和新下载立即不可见；原附件关系保留为不可用引用 |
| 恢复文件 | 30 天内且原项目有效、未归档；否则返回明确业务错误 |
| 删除项目 | 保留一期级联语义，同时软删除归属文件并记录项目删除原因 |
| 项目级联文件 | 父项目未恢复前不允许单独恢复；一期没有项目撤销删除，本期不新增该能力 |
| 到期清理 | 删除满 30 天后后台物理清理对象、提取结果和附件引用，完成后释放容量 |
| 清理失败 | 保留删除状态和容量占用，后台重试，不能标记已清理 |

直接删除与项目级联删除均在事务提交后对新请求不可见。已开始的下载可能已经交付部分或全部字节，不承诺远端撤回；后续新的请求必须重新授权并失败。回收站只处理文件，不扩展到项目、任务、笔记。

- **AC13**：跨 Workspace 的结果、摘要、标签计数和附件内容均不可访问；旧索引残留也不能泄漏已删除对象。
- **AC14**：文件删除恢复、项目级联、处理并发和到期清理满足上述规则，恢复不会突破配额或范围。

## 8 R07 可恢复处理与可观测性

后台处理必须持久化领取状态、重试次数和错误分类；服务重启后继续领取未完成任务。索引可以从业务数据和提取结果重建，不能是唯一内容存储。提供仅运维可用的重放、重建和状态检查方式。

最低记录：文件接收成功/失败、提取耗时和状态、索引延迟、任务积压、搜索耗时、对象清理失败与配额差异。日志记录 requestId、Workspace/对象内部 ID 和错误分类，不默认记录正文、完整搜索词或下载凭据。

- **AC15**：重启、重复任务、乱序更新和索引重建后数据正确；故障可由指标与 requestId 定位。

## 9 R08 可用性与兼容性

沿用一期设计系统、路由白名单、TanStack Query、保存保护和表单组件。文件、标签、搜索均提供加载、空状态、无结果、失败、只读、处理进度和权限失效视图。上传完成不能清空仍未保存的笔记草稿。

键盘可完成搜索、筛选、选择标签、上传文件选择和关闭预览；关闭弹层后焦点回到触发位置。适配 390px、768px、1440px 宽度，深浅主题均可读，尊重减少动态效果设置。

- **AC16**：一期关键路径无回归；键盘、移动布局、返回上下文和草稿保护用例通过。
